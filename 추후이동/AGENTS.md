## 프로젝트 소개

- 이름: 리뷰 온도계 API (하루마켓은 수업용 가상 쇼핑몰입니다)
- 하는 일: 리뷰 한 건과 별점을 받아 긍정/부정, 리뷰 온도(0~100℃), 별점 불일치를 알려 줍니다.
- 2차 요청: 리뷰를 쓴 고객에게 쿠폰을 줍니다.
- 한 줄 설명: <!-- 빈칸: 이 서비스를 한 문장으로, 내 말로 적어 보세요 -->
- 개발 방식: 명세(SDD) → 예시표 → 테스트(TDD) → 코드 순서로 진행합니다.

## 기준 문서

- `SPEC.md`(1차)와 `SPEC_COUPON.md`(2차)를 따릅니다. `REQUEST.md`와 다르면 SPEC을 따릅니다.
- 쿠폰 API의 주소와 필드 이름은 지금 서비스 코드(화면 `static/`이 부르는 곳)를 읽고 따릅니다. 읽은 내용은 `SPEC_COUPON.md`에 함께 적습니다. `SPEC_COUPON.md`는 사람이 쓰고, AI는 사람이 "승인"이라고 말한 뒤에만 고칩니다.
- 규칙의 숫자와 이름은 SPEC의 예시표 그대로 씁니다. 임의로 바꾸지 않습니다.

## 만드는 파일

- `app/thermo.py` : to_label, to_temperature, is_mismatch 3개 함수
- `tests/test_thermo.py` : 내가 직접 쓴 테스트 2개 + 예시표의 나머지 행 (세션 2)
- 쿠폰 API (세션 4): `SPEC_COUPON.md`를 보고 `app/schemas.py`(요청/응답 모양), `app/main.py`(주소), 규칙 함수를 만듭니다. 규칙 함수를 어느 파일에 둘지는 계획을 보고 정합니다(예: `app/coupon.py`).

## 일하는 방법

- 사용자가 이름을 말한 파일만 고칩니다. 다른 파일이 필요해 보이면 먼저 물어봅니다.
- 테스트를 쓸 때는 예시표의 행을 그대로 옮깁니다. 표에 없는 행을 마음대로 넣지 않습니다.
- 테스트가 실패하면 코드를 고칩니다. 테스트의 기대값을 바꿔서 통과시키지 않습니다.
- 테스트 값을 코드에 그대로 박아 넣지 않습니다(하드코딩 금지). 규칙으로 계산합니다.
- 새 패키지를 설치하지 않습니다. 리뷰 내용을 밖으로 보내지 않습니다. 리뷰를 저장하지 않습니다.
- 요청이 애매하면 만들기 전에 먼저 질문합니다.

## 끝났을 때 보고할 것

- `pytest -v`를 실행하고 통과(passed)와 실패(failed) 개수를 알려 줍니다.
- 바꾼 파일 목록을 알려 줍니다. `SPEC.md`와 `tests/`를 바꾸지 않았다면 그렇다고 말합니다.
- 허락 없이 고치면 안 되는 파일을 고쳤으면 무엇을 왜 고쳤는지, 안 고쳤으면 "안 고침"이라고 씁니다.
- "고쳤습니다"라고만 하지 말고, 실행한 명령과 결과를 근거로 말합니다.
